# Phase 1 compatibility and feasibility

Research date: 19 October 2026. This is an API feasibility report, not a record of successful device tests. Implementation and build status belong in the project README and validation records.

## Target and evidence boundary

The user reports an unrooted OPPO A5 Pro 5G, 8 GB physical RAM, Dimensity 6300, ColorOS 16.0.5, build `CPH2695_16.0.5.1200`. These details have **not been read from a connected phone**. Do not infer its Android API level from the ColorOS name. Read `Build.VERSION.SDK_INT`, `Build.VERSION.RELEASE`, model/manufacturer and build display at runtime; cross-check Settings > About device. The OPPO Theme Store region, launcher restrictions, live wallpaper picker and GPU blur capability require tests on that exact build.

The references describe an appearance. They do not establish that an ordinary APK can modify OPPO SystemUI or its secure lock screen. This project uses public Android APIs and leaves authentication under Android control.

Classification meanings:

- **Fully supported**: documented Android app capability; hardware validation remains necessary.
- **Partially supported**: a subset or a documented alternative is possible.
- **Requires explicit permission**: a user grant, role selection, or system confirmation is necessary.
- **Requires official OPPO theme approval**: separate OEM designer/package workflow; not supplied by normal app permissions.
- **Unsupported without privileged access**: no suitable normal-app API verified for the requested system modification.

## Module decisions

| Module / requested capability | Classification | Supported implementation and limits |
| --- | --- | --- |
| A: Custom home grid, dock, typography, drawer/search, pages, icon sizing/spacing, drag rearrangement and persisted layout | Fully supported | These are local launcher UI and storage responsibilities. Launch exported launcher activities and handle removed/disabled apps. |
| A: Become default Home and switch back | Requires explicit permission | Declare `MAIN` + `HOME` + `DEFAULT`; on API 29+ check `ROLE_HOME` availability and request it with `RoleManager`. Recheck the role on return; cancellation must preserve the prior default. Provide Home settings as fallback. [RoleManager](https://developer.android.com/reference/android/app/role/RoleManager) |
| A: Enumerate and launch applications | Partially supported | Use `LauncherApps` / matching launchable activities, not arbitrary executable packages. Declare a narrow `queries` intent for `MAIN`/`LAUNCHER` when using `PackageManager`. Profile visibility, suspended apps and private/work spaces require additional handling; do not promise unrestricted cross-profile access. [LauncherApps](https://developer.android.com/reference/android/content/pm/LauncherApps), [package visibility](https://developer.android.com/training/package-visibility/declaring) |
| A: OPPO gesture navigation and original Recents animations | Partially supported | Respect system gesture/cutout insets. A Home role grant does not make an APK the OEM privileged Recents provider. Exact transition smoothness is unverified; retain Android navigation and offer three-button navigation guidance if needed. The AOSP Quickstep manifest demonstrates its privileged integration. [gesture compatibility](https://developer.android.com/develop/ui/views/touch-and-input/gestures/gesturenav), [AOSP Quickstep](https://android.googlesource.com/platform/packages/apps/Launcher3.git/+/refs/tags/android-13.0.0_r74/quickstep/AndroidManifest.xml) |
| B: Original adaptive icons, category glyphs, assignment/cache, light/dark variants | Fully supported | Draw original resources and apply icon substitutions inside Sid Glass OS. Keep component identities and original launch targets. [adaptive icons](https://developer.android.com/develop/ui/views/launch/icon_design_adaptive) |
| B: Rewrite other applications' installed icons everywhere | Unsupported without privileged access | Launcher substitutions affect this launcher; they do not alter another signed application's resources. Stock-launcher icon-pack/theme support is a separate OEM compatibility question. |
| C: In-app glass Control Center, battery/volume/brightness and Settings shortcuts | Partially supported | Supported controls are itemized below. Clearly identify shortcut tiles, actual state and app-local controls. |
| C: Optional floating panel over other apps | Requires explicit permission | `TYPE_APPLICATION_OVERLAY` requires special overlay access. It remains below critical system windows, can be hidden/repositioned by Android, and is not the notification shade. Keep explicit launch, close and disable actions. No Accessibility workaround. [overlay window API](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY), [special permission flow](https://developer.android.com/training/permissions/requesting-special) |
| C: Restyle/replace the actual OPPO notification shade from the APK | Unsupported without privileged access | Public APIs provide app UI and individual Quick Settings tiles, not replacement SystemUI. An optional OEM theme route is described separately below. [Quick Settings tiles](https://developer.android.com/develop/ui/views/quicksettings-tiles) |
| C: Add a Quick Settings shortcut for Sid Glass OS | Requires explicit permission | `TileService`; user adds the tile, with `requestAddTileService` available from API 33. This adds one tile and does not restyle the surrounding panel. [tile documentation](https://developer.android.com/develop/ui/views/quicksettings-tiles) |
| D: Local glass notification previews | Fully supported | Label sample cards as previews. No notification access is needed to render them. |
| D: App's own posted notifications | Requires explicit permission | Use notification channels and Android's templates; request `POST_NOTIFICATIONS` on API 33+ when needed. Target API 31+ custom content is still decorated by the system, so arbitrary frosted notification surfaces are not guaranteed. [custom notifications](https://developer.android.com/develop/ui/views/notifications/custom-notification), [notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission) |
| D: Optional notification mirroring | Requires explicit permission | An enabled `NotificationListenerService` can receive permitted notifications. Local rendering does not change the originals. Respect work/profile and sensitive-content restrictions; Android 15+ may redact OTP content. Keep contents in memory only and stop/clear on revocation. [listener API](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [sensitive notifications](https://developer.android.com/about/versions/15/behavior-changes-all#otp-redaction) |
| E: Clock/date/music/shortcuts lock-screen design preview | Fully supported | Render within the application and label it a preview; it is not an authentication screen. |
| E: Set a static lock-screen wallpaper | Requires explicit permission | Explicit user action; check `isWallpaperSupported` / `isSetWallpaperAllowed` before `WallpaperManager` with `FLAG_LOCK`. Setting an image cannot change the secure clock/layout or biometric UI. [WallpaperManager](https://developer.android.com/reference/android/app/WallpaperManager) |
| E: Replace secure lock screen or inject arbitrary clock/music layouts | Unsupported without privileged access | No third-party arbitrary ColorOS secure-lock-screen layout API was verified. Never disable keyguard or present a fake security replacement. OEM theme-supported appearance changes are a separate approval route. |
| F: Native forest live wallpaper, particles, intensity/parallax/performance settings | Fully supported | Use `WallpaperService`; stop scheduled drawing when invisible/surface destroyed and release resources. Parallax depends on offsets delivered by the host. [wallpaper engine](https://developer.android.com/reference/android/service/wallpaper/WallpaperService.Engine) |
| F: Apply a live wallpaper to home / lock screen | Partially supported | Launch the public live wallpaper preview/chooser and let the system present available destinations. Home support and destination choices must be checked on-device. Separate lock-only live wallpaper support is not guaranteed; retain static lock-screen fallback. [wallpaper selection API](https://developer.android.com/reference/android/app/WallpaperManager#ACTION_CHANGE_LIVE_WALLPAPER) |
| G: Native clock/date/battery/information widgets, resizing and shortcuts | Fully supported | Publish `AppWidgetProvider` + `RemoteViews` or Glance widgets. Use host-compatible layouts and a native clock; ordinary periodic widget updates cannot be scheduled below 30 minutes through `updatePeriodMillis`. Battery freshness must be shown honestly. [widgets](https://developer.android.com/develop/ui/views/appwidgets), [widget updates](https://developer.android.com/develop/ui/views/appwidgets/advanced) |
| G: Host third-party widgets inside this launcher | Requires explicit permission | An `AppWidgetHost` is separate work from publishing widgets. Follow binding/configuration flows, retain widget IDs, and honor cancellation. [widget host](https://developer.android.com/develop/ui/views/appwidgets/host) |
| G: Other apps' music metadata/artwork/playback controls | Requires explicit permission | Cross-app active sessions need an enabled notification listener or privileged `MEDIA_CONTENT_CONTROL`; this project must use only the user-granted listener route. Some players expose no session/artwork/actions. Show a permission-off or no-session state. [MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager) |
| G: Per-pixel live backdrop blur behind external widgets | Partially supported | `RemoteViews` offers a restricted view set, not arbitrary Compose backdrop sampling. Use pre-rendered glass artwork/translucency; external host wallpaper sampling is not guaranteed. [RemoteViews](https://developer.android.com/reference/android/widget/RemoteViews) |
| H: Dashboard, local theme settings, previews, reset and reversible setup | Fully supported | Local navigation/state and supported system flows are feasible. Show current grants and actual module status; an Apply action must not imply that protected system surfaces changed. |

## Control Center action policy

| Control | Classification | API / intended behavior |
| --- | --- | --- |
| Wi-Fi / Internet | Partially supported | Apps targeting API 29+ cannot directly enable/disable Wi-Fi. Open `Settings.Panel.ACTION_INTERNET_CONNECTIVITY` or `ACTION_WIFI`, with Settings fallback; report state separately. Avoid requesting location merely to show a network name. [Android 10 restrictions](https://developer.android.com/about/versions/10/privacy/changes#enable-disable-wifi), [Settings panels](https://developer.android.com/reference/android/provider/Settings.Panel) |
| Bluetooth | Partially supported | `BluetoothAdapter.enable/disable` fail for ordinary apps targeting API 33+. Open Bluetooth Settings; a supported enable-confirmation intent is optional. Reading adapter/connected-device data may need runtime `BLUETOOTH_CONNECT` on API 31+. No grant should be requested just to launch Settings. [BluetoothAdapter](https://developer.android.com/reference/android/bluetooth/BluetoothAdapter) |
| Airplane mode | Unsupported without privileged access for direct toggle | Open `Settings.ACTION_AIRPLANE_MODE_SETTINGS`. `Settings.Global` is readable but not writable by normal apps; do not write `AIRPLANE_MODE_ON` or use hidden APIs. [Global settings](https://developer.android.com/reference/android/provider/Settings.Global), [Settings intents](https://developer.android.com/reference/android/provider/Settings) |
| Brightness in Sid Glass OS | Fully supported | Apply an app-window brightness override; label it app brightness and clear it when appropriate. It does not persist device brightness. [window brightness](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#screenBrightness) |
| Persistent device brightness | Requires explicit permission | Optional future flow: `WRITE_SETTINGS` special access and `Settings.System.canWrite`; account for automatic brightness and refresh actual values. Default fallback opens display Settings. [System settings](https://developer.android.com/reference/android/provider/Settings.System#canWrite(android.content.Context)) |
| Media volume | Fully supported | `AudioManager`, normal `MODIFY_AUDIO_SETTINGS` where required, fixed-volume checks and actual-state refresh. Use `Settings.Panel.ACTION_VOLUME` as fallback; do not silently change DND or ringer policy. [AudioManager](https://developer.android.com/reference/android/media/AudioManager), [Settings panels](https://developer.android.com/reference/android/provider/Settings.Panel) |
| Flashlight | Partially supported | `CameraManager.setTorchMode` with flash hardware/availability checks, callbacks and failure handling. The public torch method operates without opening the camera; do not request camera capture access unless implementation/device evidence requires it. Camera use/resource contention can make torch unavailable. [CameraManager torch](https://developer.android.com/reference/android/hardware/camera2/CameraManager#setTorchMode(java.lang.String,%20boolean)) |
| Battery/charging | Fully supported | Read `BatteryManager` / battery broadcast while visible; no private battery-history access or polling service is necessary. [BatteryManager](https://developer.android.com/reference/android/os/BatteryManager) |
| Dark mode | Partially supported | Theme Sid Glass OS locally. Global dark-mode control is not verified on the target ColorOS build, so open display Settings for system changes. `setApplicationNightMode` changes this app; never report it as a system change. [UiModeManager](https://developer.android.com/reference/android/app/UiModeManager#setApplicationNightMode(int)) |

Every Settings intent must tolerate absent handlers/security failures, offer general Settings fallback, and refresh real state on return. Opening Settings is not proof of a successful change.

### Initial Control Center implementation scope

The initial implementation provides the in-app panel, actual media-volume control, explicitly labeled app-window brightness, battery/charging, Wi-Fi connection status without SSID/location access, supported flashlight control and protected-settings shortcuts. Flashlight work/callbacks stop with the visible screen, and a flashlight enabled here is switched off when leaving. A user-added Quick Settings tile opens this panel; it does not replace the system shade.

Music cards and the native music widget optionally connect to active media sessions through an explicitly enabled notification listener. A privacy explanation precedes Android's grant settings. Supported transport actions and track changes follow real session callbacks; absent access/session/metadata/actions retain useful fallbacks. Notification contents are ignored, and media data is not persisted or uploaded. The listener's API31+ default content filter is empty: official documentation says this allows no notification types. The enabled listener grant separately authorizes `MediaSessionManager`; exact OEM behavior remains a device test. [Notification listener filters](https://developer.android.com/reference/android/service/notification/NotificationListenerService#META_DATA_DEFAULT_FILTER_TYPES), [session access](https://developer.android.com/reference/android/media/session/MediaSessionManager#getActiveSessions(android.content.ComponentName))

Notification mirroring, global brightness writes and floating overlays are not implemented. No special-permission prompt is shown for absent features, and previews do not claim to control the system. The compatibility table records both feasibility and the limits of this release.

## Real blur and performance

`RenderEffect`/Compose layer blur acts on rendered content; applying it to a card does not automatically sample the pixels behind that card. Android 12/API 31+ cross-window background/behind blur is a different facility, requires appropriate translucent window configuration and is supported only on selected devices. [AOSP window blurs](https://source.android.com/docs/core/display/window-blurs)

Check `WindowManager.isCrossWindowBlurEnabled` and register/unregister its change listener. Blur can turn off at runtime in battery saver or due to GPU/output conditions. A readable translucent fill and border must remain when blur disappears. Use cached, downsampled pre-blurred **app-owned** forest artwork for internal cards where useful, without claiming it is live system backdrop blur. [WindowManager](https://developer.android.com/reference/android/view/WindowManager#isCrossWindowBlurEnabled())

Balanced is the default design target; cap wallpaper rendering, reduce particles/motion in Battery Saver, and stop invisible work. Measure startup, frame times, memory and battery on the actual device before claiming a frame-rate or battery result.

## OPPO Theme Store route: separate from the APK

OPPO's official Chinese developer portal has a **ColorOS16 theme adaptation guide**. It describes OS-specific global packages, a resource whitelist/editor export, versioned modules and review requirements. Its module table includes `com.android.systemui` (Control/Notification Center and other system surfaces), launcher/icons/wallpaper and live wallpaper. This is evidence of an OEM theme workflow, **not** a public API authorizing arbitrary APK modifications. [ColorOS16 theme adaptation guide](https://open.oppomobile.com/documentation/page/info?id=13718)

The official Theme Store introduction describes identity verification and designer qualification review. Obtaining the current editor, meeting asset/review rules, exporting a compliant package and obtaining the appropriate approval are separate work. Region/account eligibility, package signing/distribution, current export extension, personal-file import and applicability to this exact CPH2695 global/India build have **not** been verified. Do not generate a renamed ZIP or claim that a `.theme` file will install. [OPPO Theme Store developer introduction](https://open.oppomobile.com/new/introduction?page_name=theme)

OPPO documents user-controlled wallpaper choices under ColorOS 16's Home screen, Lock screen & style settings. Its Chinese support site also describes selected built-in lock-screen widgets through inspiration themes; that does not establish a general third-party widget/layout API or availability in the user's region. [OPPO wallpaper support](https://support.oppo.com/in/answer/?aid=neu133), [OPPO lock-screen widget support](https://support.oppo.com/cn/answer/?aid=2269153)

**Decision:** build an independent, reversible native launcher/customization app. Keep official theme production as a separately documented possibility until the current editor, approval path and target-device support are verified. No root, security disabling, Accessibility automation, protected-resource patching or unverified theme installation is part of this project.
